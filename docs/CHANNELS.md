# チャンネル管理

## 📖 概要

クラブ・イベント・プロジェクトのチャンネルとロールを作り、アーカイブ・復元し、参加者を出し入れする機能です。3種類とも同じコマンドで操作します。チャンネルとロールは**番号**（`c001` / `e001` / `p001`）で結びつきます（用語は[CONTEXT.md](../CONTEXT.md)）。

| コマンド | 内容 |
|---|---|
| `/create_channel category channel_name [members]` | チャンネルとロールを作成。`category`で種類を選ぶ |
| `/archive_channel [channel]` | その種類のアーカイブカテゴリへ移す |
| `/restore_channel [channel]` | その種類の通常のカテゴリへ戻す |
| `/add_role_members members [role]` | ロールに参加者を加える |
| `/remove_role_members members [role]` | ロールから参加者を外す |

作成以外は、対象のチャンネル（アーカイブ・復元）やロール（参加者の出し入れ）から種類を判定するので、種類を指定しません。`channel`・`role`を省略すると、実行したチャンネル（スレッドなら親チャンネル）が対象になります。

コマンドはDiscordに慣れた人向けです。慣れていない人は、ボタンとフォームだけで操作できる[パネル](#パネル)を使います。コマンドとパネルは同じ処理（`channel_actions.py`）を呼びます。

## 🏗️ 構成

```
src/commands/channel.py             # 5つのコマンド
src/commands/panel.py               # /intech、/setup_panel、パネルのボタンの処理

src/utils/
├── channel_actions.py              # 作成・アーカイブ・復元・参加者の出し入れの本体（コマンドとパネルから呼ぶ）
├── panel.py                        # パネルの表示、ボタン、ピン留めのパネルを探して書き換える
├── panel_forms.py                  # パネルから開くフォーム
├── kinds.py                        # 種類ごとの違い（頭文字・ラベル・ロール名の規則）
├── linking.py                      # 番号によるチャンネルとロールの紐づけ
├── numbering.py                    # 番号の採番と読み取り
├── creation.py                     # 作成の共通処理（上限チェック・ロールバック・ロールの移動）
├── role_order.py                   # 作成したロールの置き場所
├── channel_order.py                # 移動と、移動先カテゴリの並べ直し
├── role_utils.py                   # ロールの付与と削除
└── records.py                      # 記録
```

### 種類ごとの違い

| 種類 | チャンネル名 | ロール名 | カテゴリ（環境変数） |
|---|---|---|---|
| クラブ | `c001-ラーメン` | `c001-ラーメン`（番号＋名前） | `CLUB_CATEGORY_NAME` / `ARCHIVE_CLUB_CATEGORY_NAME` |
| イベント | `e001-おでん会` | `e001`（番号のみ） | `EVENT_CATEGORY_NAME` / `ARCHIVE_EVENT_CATEGORY_NAME` |
| プロジェクト | `p001-ハッカソン` | `p001`（番号のみ） | `PROJECT_CATEGORY_NAME` / `ARCHIVE_PROJECT_CATEGORY_NAME` |

クラブは常設なので、メンションしたときに何のクラブか分かるよう、ロール名に名前も含めます。アーカイブカテゴリは種類ごとに分けます（並べ直しが種類の番号順で行うため）。同じカテゴリを共有する設定にした場合も、チャンネル名の頭文字で種類を判定するので別の種類のカテゴリへ戻ることはありませんが、並べ直しは1つの種類の番号でしか行われません。

## 🔧 実装詳細

### 作成

```mermaid
sequenceDiagram
    participant User
    participant Bot
    participant Discord

    User->>Bot: /create_channel category:イベント
    Bot->>Bot: defer（本人だけに見える）
    Note over Bot: ここから作成用のLock内
    Bot->>Bot: 上限チェック
    Bot->>Bot: 番号を採番
    Bot->>Discord: チャンネル作成
    Bot->>Discord: ロール作成（失敗したらチャンネルを削除）
    Bot->>Discord: ロールを同じ種類のロールの一番下へ移動
    Note over Bot: Lockを解放
    Bot->>Discord: 本人と指定メンバーにロール付与
    Bot->>User: 結果（本人にだけ表示）
    Bot->>Discord: チャンネル内に記録
```

### 番号での紐づけ

チャンネルとロールは、名前の先頭の番号で結びつけます（`linking.py`）。名前の部分はDiscordの正規化（小文字化、空白をハイフンに、など）でずれることがありますが、番号はずれません。

参加者の追加・削除は、次をすべて満たすロールだけを操作します。

1. ロール名が種類の形をしている（club: `cNNN-名前`、event: `eNNN`、project: `pNNN`）
2. 同じ番号のロールがほかにない
3. 同じ番号のチャンネルが、その種類の通常のカテゴリかアーカイブカテゴリにちょうど1つある
4. 管理者ロールなどの重要なロールではない（`validate_role_safety`）

番号が重なるのは手作業で名前を変えた場合だけですが、どれを使うか決められないのでエラーにします。

### 番号の採番

その種類の通常のカテゴリとアーカイブカテゴリにあるチャンネル名、およびロール名のうち、種類の頭文字の番号の最大に1を足します（`channel_utils.py`の`get_next_number`）。欠番は埋めません。ロール名も見るのは、チャンネルだけ消されてロールが残っている番号を再利用しないためです。999を使い切ったら作成を拒否します。

### アーカイブ・復元

対象チャンネルのあるカテゴリから種類と「アーカイブ中かどうか」を決め（`linking.py`の`locate_channel`）、反対側のカテゴリへ移したあと、移動先をその種類の番号順に並べ直します（`channel_order.py`の`move_channel`）。アーカイブの記録は、アーカイブ先でbotが送信できない可能性があるため移動の**前**に投稿し、移動に失敗したら消します。

### 投稿による自動復元

アーカイブ中のチャンネル（またはそのスレッド）に人が投稿すると、botがその種類の通常のカテゴリへ戻します（`auto_restore.py`の`restore_on_post`、`bot.py`の`on_message`から呼ぶ）。アーカイブカテゴリの権限で、メンバーが送信できるようにしておく必要があります。

- botとwebhookの投稿、ピン留めやスレッド作成などのシステムメッセージは数えない。リアクションも数えない
- 番号のないチャンネル（アーカイブカテゴリに置いた案内など）は自動では戻さない
- 連投で二重に戻さないよう、チャンネルごとに直列化し、移動の直前に最新のカテゴリを取り直して確かめる
- 戻したら「@x がメッセージを送ったので、`📅 イベント` カテゴリーに戻しました」をチャンネル内に記録する（通知はしない）
- 戻し先のカテゴリが上限（50）なら戻さず、その投稿に返信で理由を伝える
- 移動に失敗したら、その投稿に返信で戻せなかったことを伝え、warningを出す（例外は出さない）

### 参加者の削除

外された人には通知しません。チャンネル内の記録には誰が誰を外したかを残しますが、メンションはEmbedの中にだけ書きます（Embed内のメンションは通知されない）。

## 🎛️ パネル

作るなら案内チャンネル、操作するならそのチャンネルのピン留め。どちらもボタンだけで、コマンドは要りません。`/intech`は、その場所のパネルを本人にだけ出します（番号のついたクラブ・イベント・プロジェクトのチャンネルとそのスレッドではチャンネルのパネル、それ以外では作るパネル）。

```mermaid
flowchart LR
    G[案内チャンネルの<br/>作るパネル] -->|作る| F[フォーム]
    I1["外で /intech"] -->|本人にだけ| G
    F --> C[新しいチャンネル<br/>ピン留めのチャンネルのパネル]
    I2["チャンネルの中で /intech"] -->|本人にだけ| C
    C -->|参加者を追加・外す| F
```

### 作るパネル

- 見出し「チャンネルを作る」、説明「誰でも作れます」、ボタン「イベントを作る」「プロジェクトを作る」「クラブを作る」
- フォーム: 名前（入力前に「例: おでん会」、下に「番号（e013 など）は自動で付きます」。番号はフォームを開いた時点の見込み）と、「他の参加者（任意）」のメンバー選択（最大25人）
- 作成の返信に、チャンネルへのリンクと「参加したい人には、このチャンネルを伝えてください。チャンネルのピン留めから参加できます。」を出す
- 案内チャンネルには`/setup_panel`で置く

### チャンネルのパネル

- 作成したチャンネルに投稿してピン留めする。作成の記録（履歴）とは別のメッセージにする。ピン留めできなければ投稿を取り下げ、操作した人にbotの権限を確認して`/setup_panel`で置き直すよう伝える（パネルはピン留めから探すので、ピン留めされていないパネルは書き換わらず、置き直すと重複するため）
- 参加者の一覧を表示する。20人を超えたら「ほかN人」と「全員を見る」ボタン（本人にだけ全員を表示）
- ボタン: 「参加する」「抜ける」「参加者を追加」「参加者を外す」「アーカイブ」（アーカイブ中は「復元」）。全員に同じ表示しか出せないので、参加と抜けるは2つのボタンにする
- 「参加者を追加」「参加者を外す」はフォームでメンバーを選ぶ（1人以上）。フォームを開いている間にアーカイブなどされることがあるので、送った時点でチャンネルとロールを紐づけ直す。「アーカイブ」は本人にだけ確認を挟む
- 管理者権限を持つロールなどは、誰でも押せるボタンからは付け外ししない（`validate_role_safety`）
- 既存のチャンネルには`/setup_panel`で置く

### 見た目

パネルはComponents V2（`LayoutView`）で組みます。置いたまま見続ける画面なので、「誰が参加しているか」と「何ができるか」を形で分けるためです。本人にだけ出す確認や返信は、ほかの返信とそろえてEmbedのままにします。

```text
┃ ### #e003-おでん会
┃ 📦 アーカイブ中（このチャンネルでメッセージを送ると戻ります）   ← アーカイブ中だけ
┃ 参加者（23人）
┃ @a, @b, … ほか3人                           [全員を見る]   ← 20人を超えたときだけ
┃ ───────────────
┃ [参加する] [抜ける]                                        ← 自分のこと
┃ [参加者を追加] [参加者を外す] [アーカイブ / 復元]             ← みんなのこと
```

- 枠の色は、ふだんは青、アーカイブ中は灰色
- 一覧はメンションで並べるが、本文扱いになるので、送る・書き換えるときは`allowed_mentions`で鳴らさない
- Components V2のボタンは枠や行の中に入れ子で届くので、パネルを探すときは入れ子をたどる

### ボタンの仕組み

- ボタンは`discord.ui.DynamicItem`で、custom_idに操作とチャンネルのIDを埋める（`intech:channel:join:<チャンネルID>`、`intech:create:event`）。botの再起動後も、custom_idからボタンを作り直して処理する。DBは要らない
- 押されるたびに、IDからチャンネルを取り、番号でロールを紐づけ直す。手でロールを付け外ししても、次に押されたときの一覧には反映される
- `panel.py`はボタンが押されたときの処理を知らない。処理は`commands/panel.py`が登録時に渡す（`set_channel_press_handler`）。`panel.py`を作成などの処理から呼べるようにするため

### パネルの書き換え

参加者の顔ぶれやアーカイブの状態が変わったら、ピン留めのパネルを書き換えます（コマンド・パネル・投稿による自動復元のどれでも）。

- ピン留めの中から、botが投稿した、チャンネルのパネルのボタンを持つメッセージを探す（`find_panel`）。見つからなければ何もしない
- ロールの付け外しはgatewayのイベントが届くまで`role.members`に反映されないので、直前に付け外しした人を呼び出し側から渡して一覧に反映する
- 移動の直後はキャッシュのカテゴリが古いので、アーカイブ中かどうかは呼び出し側から渡す
- 本人にだけ出したパネル（`/intech`）は書き換えない。ボタンは押されるたびに今の状態で処理する
- 書き換えに失敗しても操作は成功扱いにし、warningを出す

## 🐛 トラブルシューティング

### Q: ロールに参加者を追加できない

**原因:**
1. ロール名が種類の形をしていない、または同じ番号のチャンネルがその種類のカテゴリにない
2. 同じ番号のロールやチャンネルが複数ある
3. 管理者ロールなど重要なロールを操作しようとしている

**解決策:**
- チャンネル名とロール名の番号を手で揃える
